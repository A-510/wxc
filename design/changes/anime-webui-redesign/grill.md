# Grill: 挑战这次请求（对照 PLAN.md / README.md / 代码）

`/grill-with-docs` 在本环境不可用，这里逐条把请求压到产品文档与代码事实上，记录结论。

## 1. 「日式二次元」会不会和运维工具的可读性打架？

文档事实：README 把界面定位成「捕获列表 / 批量下载 / 进度 / 改名 / 忽略删除 / 手动导入 / 开关代理」，是**高频重复使用的操作界面**，不是展示页。
结论：二次元只允许出现在**材料、色彩、图形、字体排版**上（玻璃面板、青海波纹样、番札标签、插画背景），**不允许**改变信息架构（不加 hero、不把表格改成卡片墙）。风格服从扫读效率，风格冲突时让风格退让。

## 2. 那张插画是什么，能不能随便用？

事实：`背景.jpg` 是 3840×2160 的官方画风插画（© HoYoverse 系作品素材），用户自有文件。工具是本机个人离线学习用，不上传、不再分发。
结论：可用，但在 `DESIGN.md` 里记为**非商用、仅本机个人使用**，并写清替换点（`--art` 只依赖一条路由，换任何等比例图都能用）。若将来要公开分发/开源，必须先替换该素材——这条写进 `Do's and Don'ts`。

## 3. 要不要引入字体/图标库/CDN？

事实：README 明确「single page 无构建步骤」，环境是离线本机。
结论：不引入。CJK 用系统栈；图标用内联 SVG；插画用本地文件。任何 `http(s)://` 外部请求都视为缺陷。

## 4. 需要改后端吗？

事实：`wxc/webui.py` 只有 `GET /` 直接 `read_text()` 返回 `static/index.html`，没有 `StaticFiles` 挂载，也没有服务图片的路由；`/files/{name}` 走下载库，不能复用。
结论：新增**一条只读路由**提供背景插画（`GET /art/background`，读项目根的 `背景.jpg`，路径固定、无参数、缺失时返回 404 让页面优雅降级）。不改任何 `/api/*` 契约。

## 5. 四步流程要不要做成分步向导？

事实：抓包是后台异步的（微信里播放才产生条目），工具无法判断「用户是否已经播放过」。
结论：不做向导。做成**常驻的四步轨道（stepper）**，用 `/api/status` 里已有的 `cert.installed / proxy.enabled / capture_running / counts.total` 实时点亮，把「我现在卡在哪一步」直接摊开。

## 6. 动效范围？

结论：只做状态反馈类（悬停、焦点、状态切换、确定/不确定进度）。不做入场动画、滚动动效、飘落花瓣——后者是装饰，且与 MOTION.md 的 minimal posture 冲突，还会在长时间挂着的下载页里持续耗电。

## 7. 会不会顺手把别的也改了？

事实：PLAN.md M4 已把界面范围定死；M5 自检脚本 `scripts/selftest.py` 只验证抓包/下载层，不依赖界面 DOM。
结论：本次只碰 `static/index.html` 与 `wxc/webui.py`（+1 路由）。`selftest.py` 无需改动，改完必须跑一次确认后端没被带坏。

## 8. 已知未决/风险

- 插画是大面积亮色，玻璃面板必须带足够不透明度；最终以对比度实测为准，不靠眼估。
- Windows 不同机器的系统 CJK 字体可能不同（雅黑/等线/思源），栈必须给出回退链并在 200% 缩放下验证。
